================================================================================
  БАШНЯ 100 ИСПИТАНИЙ — ПОДРОБНЫЙ ГАЙД ДЛЯ РЕДАКТОРА
  Как менять силу монстров, характеристики предметов, зоны/этажи и связанные
  настройки. Каталог: tower_bot. Сверяйтесь также с файлом
  «СПРАВОЧНИК_ПРЕДМЕТЫ_МОНСТРЫ_ЛУТ.txt» (сводка по коду).
================================================================================

ВАЖНО
  • Работайте в папке проекта с ботом: .../tower_bot/ (корень пакетов game/, services/,
    bot/ и т.д.).
  • После правок Python-файлов перезапустите процесс бота, чтобы подтянулся код.
  • Смена «схемы» БД (миграции) не требуется для обычного баланса: зона, статы
    в JSON предметов, константы в balance.py — это код, а не миграции.
  • В бою итоговые цифры монстра собираются в services/combat_service.py
    (функция _monster_stat_bundle), а кривые — в game/balance.py.

================================================================================
0. КАТАЛОГ МОНСТРОВ В PYTHON (явные цифры, фразы, золото/опыт)
================================================================================

  Сборка:  game/floors/monster_defs/registry.py
  Доступ:  get_all_definitions() — словарь id → карточка (как в JSON-примере).
  Мост в бой:  game/floors/monster_catalog.py (читает реестр).

  Большинство записей собираются автоматически: снимок той же формулы, что в
  game/floors/monster_stat_formula.py, на «эталонном» этаже зоны (середина
  диапазона; мини/первый мини-этаж; мажор/первый босс-этаж). Для мини/мажор
  в карточке стоит catalog_skip_spawn_mults=True (роль не умножается дважды в бою).

  Ручные правки: константа ICE_ELEMENTAL_OVERRIDE в registry.py (или отдельный
  словарь-оверрайд по id после сборки).

  Поля карточки: id, name, level, reference_floor, hp, atk, def, exp, gold, element,
  phrases, skills, loot_table, image, catalog_skip_spawn_mults.

  Новый монстр: 1) MonsterTemplate в game/floors/monsters.py  2) при необходимости
  строка в ICE_ELEMENTAL_OVERRIDE / своя запись, либо дождаться пересборки из формулы.

================================================================================
1. МОНСТРЫ: ОТКУДА БЕРУТСЯ HP / АТАКА / ЗАЩИТА
================================================================================

1.1. Главный файл кривых
  Файл:  game/balance.py

  Здесь заданы:
    • База и рост сырого HP, атаки, защиты: MONSTER_HP_*, MONSTER_ATK_*, MONSTER_DEF_*
    • Множители типа цели: элита, мини-босс, сильный босс (MONSTER_MULT_*)
    • «Поздние» этажи: MONSTER_LATE_FLOOR_THRESHOLD, MONSTER_LATE_HP_MULT, …
    • Масштаб силы с этажом: monster_tower_floor_strength_multiplier
        (MONSTER_TOWER_SCALING_BASE, CAP)
    • Порог 5-го этажа: мини-босс, кап HP, MONSTER_FLOOR5_*
    • С 6-го этажа: MONSTER_POST_FLOOR5_EXTRA_MULT_PER_FLOOR
    • Босс 10-го: MONSTER_FLOOR10_MAJOR_BOSS_MULT
    • Босс 20-го (слизневый король): MONSTER_FLOOR20_SLIME_KING_*
    • С 12-го: MONSTER_HP_FLOOR12_*
    • Этажи 18–19: MONSTER_FLOOR18_19_*
    • Плоские бонусы к удару: MONSTER_ATK_FLAT_NORMAL / ELITE
    • Как урон по игроку обрабатывается: MONSTER_DAMAGE_DEALT_MULT, MONSTER_ARMOR_PENETRATION
    • Награды за бой, шансы руны, шанс дропа: GOLD_*, XP_*, RUNE_CHANCE_*, DROP_CHANCE_*
    • Порог золота с этажом: DEATH_GOLD_LOSS_*, и т.д.

  Как «сделать мобов слабее/сильнее везде»:
    — Снизьте MONSTER_TOWER_SCALING_BASE (рост с этажом) или MONSTER_HP_CURVE_MULT /
      MONSTER_ATK_CURVE_MULT.
    — Для «только поздняя игра» — трогайте MONSTER_LATE_*, MONSTER_POST_FLOOR5_*.

1.2. Сборка итоговых цифр в бою
  Файл:  services/combat_service.py
  Функция:  _monster_stat_bundle(floor_number, spawn)

  Здесь по шагам умножаются базовые формулы из balance.py на тип спавна (элита/
  мини/мажор), пороговые этажи (5, 10, 12, 18–19, 20 для короля слизней), и т.д.

  Если нужно добавить отдельное правило «на этаже N множитель X»:
    • Чаще всего достаточно добавить константу в balance.py и блок if в
      _monster_stat_bundle по аналогии с уже существующими ветками.

1.3. Имена, эмодзи, стихии — не статы
  Файл:  game/floors/monsters.py

  MonsterTemplate(key, name, emoji, element, blurb) — описание для UI и элемента в бою.
  Пул монстров по зоне — словарь _pool → zone_key.

  Изменить «какие твари водятся в зоне»:
    • Редактируйте кортежи MonsterTemplate внутри _pool для нужного zone_key.
    • Ключ key должен быть уникален в рамках здравого смысла (используется в дропе,
      хеше ослаблений и т.п.).

  Мини-босс и сильный босс зоны задаются отдельно:
    • mini_boss_for_zone(...)
    • major_boss_for_zone(...)
  Можно сменить шаблон (имя, emoji, element) без смены глобального баланса.

1.4. Логика «какие цели на этаже»
  Файл:  game/floors/monsters.py — build_spawns_for_floor(floor_number)

  Правила:
    • Этаж 3: пустой список (только город).
    • Этаж 100: один сильный босс финала.
    • Иначе: 6 обычных + элита + при необходимости мини-босс (×5 не ×10) и мажор (×10).

  Условия «каждый 5-й / 10-й этаж» — в game/floors/floor_data.py:
    is_mini_boss_floor, is_major_boss_floor.

  Отдельный режим «длинный этаж» — game/floors/long_floor.py (например этаж 15).

================================================================================
2. ЭТАЖИ И ЗОНЫ: КАК ПЕРЕСТРОИТЬ БАШНЮ ПОД СЕБЯ
================================================================================

2.1. Диапазоны этажей по зонам
  Файл:  game/floors/floor_data.py

  Кортеж ZONES: для каждой ZoneInfo заданы floor_from, floor_to, имя, описание.

  Пример изменения «Лес дольше»:
    • У forest_beginnings расширить floor_to (например до 15).
    • У следующей зоны сдвинуть floor_from, чтобы не было разрыва и пересечений.

  Функция get_zone_for_floor(floor_number) проходит по ZONES по порядку — держите
  диапазоны непересекающимися и покрывающими 1–99 (этаж 100 — ZONE_FINAL отдельно).

2.2. Финальный этаж
  ZONE_FINAL в том же файле — этаж 100, ключ tower_warden.

2.3. Города-хабы
  Словарь CITIES: ключ — номер этажа (3, 31, 61, 91). Можно добавить город на другой
  этаж, но тогда проверьте:
    • Логику торговцев/NPC: has_trader, has_quest_npc в floor_data.py;
    • Тексты городов и квесты, если они завязаны на номер этажа.

2.4. Названия «комнат» на карте этажа
  EPITHETS по zone.key — строки для ротации подписей; epithet_for_floor берёт индекс
  по номеру этажа.

2.5. Портал быстрого перехода из меню
  Файл:  game/floors/portal.py
  Константа PORTAL_DESTINATION_FLOORS — кортеж этажей. Игрок может перейти только если
  highest_floor_reached >= цели.

2.6. Опыт и «зоны» для прокачки
  Файл:  game/balance.py — ZONE_MULTIPLIER_BY_MAX_FLOOR
        game/characters/progression.py — zone_multiplier_for_floor

  Это множитель порога опыта до следующего уровня, не прямо «сложность этажа».

================================================================================
3. ПРЕДМЕТЫ: ЭКИПИРОВКА ИЗ КАТАЛОГА
================================================================================

3.1. Где лежат карточки предметов
  Папка:  game/items/equipment/catalog/

  Файлы по типам слотов/оружия, например:
    weapons.py, chest_armor.py, gloves.py, helmet.py, pants.py, rings.py, offhand.py …

  Каждый предмет — словарь Python с полями вида:
    kind      — weapon | armor | gloves | … (как ожидает инвентарь)
    rarity    — common | uncommon | rare | epic | legendary (по принятой схеме проекта)
    attack    — для оружия
    defense   — для брони/аксессуаров
    str/dex/int/vit/luck — опционально, бонусы статов
    weapon_type — blade, axe, staff, … (для оружия)
    summary, name, image_url и др.

  Списки собираются через finalize_stub_list из _stub_utils.py — при добавлении новой
  записи копируйте структуру у соседних предметов того же файла.

3.2. Регистрация каталога в общем пуле
  Файл-сводка:  game/items/equipment/catalog_generated.py
  Функция all_example_groups() собирает словари из модулей catalog/*.py (weapon_main_examples,
  armor_examples и т.д.).

  • Если вы только правите записи внутри существующего файла (например weapons.py) —
    переподключать ничего не нужно.
  • Если добавляете новый файл каталога с новой функцией-поставщиком — импортируйте её
    в catalog_generated.py и добавьте ключ в словарь all_example_groups().

================================================================================
4. ЛУТ ПОСЛЕ БОЯ: ШАНСЫ И ЦИФРЫ ВЫПАДЕНИЯ
================================================================================

4.1. Шансы дропа и рун из balance.py
  DROP_CHANCE_NORMAL / ELITE / MINI / MAJOR
  DROP_CHANCE_MULT_FLOORS_1_TO_5 и DROP_CHANCE_MULT_FLOOR_6_PLUS — поправка по этажу.
  RUNE_CHANCE_* — отдельные шансы рунного камня.

  Применение — сервис боя (combat_service): roll_item_drop, roll_rune_stone и т.д.

4.2. Что именно выпало при успешном дропе
  Файл:  game/items/loot.py

  Функция roll_victory_item_payload(floor_number, spawn) ветвится по типу цели:
    мажор-босс → _major_boss_loot, мини → _mini_boss_loot, элита → _elite_loot,
    обычный → _normal_loot.

  Внутри — готовые dict payload’ы (имя, kind, rarity, defense, attack, …). Чтобы
  изменить «что падает с обычного моба на 40 этаже», правьте веса в _weighted_payload
  и сами словари в соответствующих *_loot функциях.

4.3. Скейлинг цифр лута по этажу
  Файл:  game/items/loot_scaling.py

  Функции вида normal_gloves_defense(fl), normal_weapon_attack_low(fl), … — единая точка,
  если нужно «в целом поднять защиту дропа с этажа».

================================================================================
7. КРАТКИЙ ЧЕКЛИСТ «ЧТО ТРОНУТЬ ДЛЯ ЗАДАЧИ»
================================================================================

  Сделать всех мобов жёстче на высоких этажах     → balance.py (tower scaling, late game)
  Ослабить только элит/боссов                    → MONSTER_MULT_* и ветки в
                                                   _monster_stat_bundle
  Поменять набор тварей в зоне                   → monsters.py _pool, при желании
                                                   mini_boss/major_boss таблицы
  Перенести границы зон (1–10 → 1–12)            → floor_data.py ZONES (+ тексты квестов)
  Изменить шанс трофея / эликсира                → balance.py DROP_* ; детали таблиц —
                                                   loot.py
  Изменить цифры на выпадающем оружии           → loot_scaling.py и/или dict’ы в loot.py
  Отдельный баланс каталога лавки               → equipment/catalog/*.py

================================================================================
Конец гайда. При сомнениях ищите по коду символы из balance.py (например
MONSTER_MULT_ELITE_HP) — так найдёте все места использования.
